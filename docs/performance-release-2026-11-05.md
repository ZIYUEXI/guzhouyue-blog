## 后台编辑页

固定 `.typora-shell` 水纹，消除 `background-position` 动画持续重绘整篇文章；输入后的全文序列化间隔由 180ms 调为 350ms，重复标脏状态不再触发更新。

验收进一步发现既有 MDXEditor 补丁忽略静音的外部文档更新：恢复内容已经显示，`getMarkdown()` 却可能返回旧快照。已修正外部更新的内部 Markdown 同步，保存与切换操作直接采用编辑器返回的最新快照。

在生产数据库的隔离副本上，用用户反馈的《跑通了，不一定对：我如何被自己的自测骗过》执行：

- 连续输入后立即保存：数据库包含末尾 marker，原作者保留。
- 纯编辑 → 所见即所得：公式、代码块及语言标记保留。
- 自动保存 → 刷新 → 恢复草稿 → 直接保存：数据库中末尾 marker、公式、Python 代码及作者逐项核对成功。
- 首次保存失败提示曾由测试代理漏实现 PUT/DELETE 引起，已补测试代理；产品的本地草稿回退提示正常。

相同机器的本地样本中，编辑页初始 12 秒帧间隔 P95 约 33.4ms → 16.8ms。输入事件至两次 rAF 的样本存在约 31–44ms 波动，尚不能认定输入延迟稳定下降；该采样也不等同于正式 INP。上线验收通过 SSH 隧道查看实际 Nginx 管理页及该文章，正文与署名正常，未对生产文章做输入或保存测试。
